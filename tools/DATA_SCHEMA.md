# 编年史数据分片编写契约（Data Authoring Contract）v1

所有数据分片必须严格遵守本文件。校验脚本 `tools/validate.mjs` 会按此判定错误。

## 1. 文件形态

零构建、`file://` 双击可运行 ⇒ **禁止 `export`/`import`/`fetch`**。每个分片是普通 `<script>` 文件，形态固定：

```js
/* chronicle data chunk: cn-02 | 春秋战国 前841–前221 | 生成于 2026-09-21 */
window.__CHRONICLE_CHUNK = window.__CHRONICLE_CHUNK || {};
window.__CHRONICLE_CHUNK["cn-02"] = [
  { /* event 1 */ },
  { /* event 2 */ }
];
```

- 文件必须是合法 JavaScript，能被 `node --input-type=module` 或直接 `node -e "require"` 方式加载（用 `global.window={}` 垫片）。
- 每条事件占**一行**（不换行），便于 diff 与定位。允许长行。
- UTF-8，中文不转义，不用 `\uXXXX`。
- 字符串内若需引号，用中文引号「」或“”，避免转义地狱。

## 2. 事件对象 schema

```js
{
  id: "cn--b636--pNN",
  track: "cn",                 // "cn" | "world"  —— 必须与 id 前缀一致
  year: -636,                  // 整数；公元前为负；不存在 0 年（-1 与 1 相邻）；范围 [-3000, 2026]
  yearApprox: false,           // 年代为学界推定/有争议 → true，界面显示 "~前2070年"
  dim: "politics",             // 见 §3 十维枚举，必须精确匹配
  weight: 4,                   // 1–5 整数，见 §4
  title: "晋文公即位",           // ≤ 24 字
  summary: "重耳结束十九年流亡归国为君，次年城濮之战称霸。",  // ≤ 45 字，悬停气泡用
  detail: {
    background: "……",           // 背景与缘起，1–3 句
    process: "……",              // 经过，2–5 句，含具体时间/地点/关键动作
    impact: "……",               // 影响与意义，1–3 句
    figures: ["重耳","狐偃","先轸"],   // 1–8 个关键人物，中文全名
    place: "晋（今山西翼城一带）",      // 地点，古今对照
    state: "晋国",                     // 政权/国家/文明，用于筛选与对照
    sources: ["《史记·晋世家》","《左传·僖公二十四年》"],  // ≥1 项，见 §6
    tags: ["春秋","霸主政治"]            // 2–5 个标签
  },
  // 下列两个 id 为占位示意（seq 写作 NN）；真实条目里 related 必须指向盘上存在的 id
  related: ["world--b636--pNN","cn--b632--mNN"],  // 0–4 项，必须指向真实存在的 id（禁悬空）
  checks: [ { by: "张三（翻中华书局点校本《史记》卷三九）", at: "2026-09-20", note: "原文作\"二年\"，条目误\"元年\"" } ]
  // 可选。核对记录：唯一能把溯源等级抬到「已核」的输入，见 §6A
}
```

字段全部**必填**（`related` 与 `checks` 可为空数组或整项省略）。不得新增未定义字段。

## 3. 维度枚举（`dim`）

| key | 中文 | 口径 |
|---|---|---|
| `politics` | 国家政治 | 政权更迭、即位、篡夺、变法、外交会盟、统一与分裂、条约 |
| `figure` | 关键人物 | 核心人物的生卒、关键抉择、独立于事件的人格性节点 |
| `science` | 科技进步 | 发明、发现、工程、天文历法、医学、农具、算学、通信技术 |
| `culture` | 人文思想 | 哲学、宗教创立与传播、教育、学术范式、史学、思想论争 |
| `art` | 文学艺术 | 文学、音乐、绘画、雕塑、建筑作品、戏曲、书法 |
| `military` | 军事战争 | 战役、征服、军制改革、兵学著作、武器变革 |
| `economy` | 经济社会 | 贸易、货币、赋税、人口、城市化、民生、产业 |
| `institution` | 制度法律 | 官制、律令、科举/选官、土地制度、历法制度、行政建制 |
| `explore` | 地理探索 | 航行、地理发现、旅行记、疆域勘察、地图学 |
| `disaster` | 灾害疫情 | 灾荒、瘟疫、地震、洪水、气候事件及其社会后果 |

一条事件只归一个 `dim`（取其最主要面）。城濮之战归 `military`，晋文公称霸归 `politics`，二者用 `related` 连接。

## 4. `weight` 重要度判定

- **5** 改变文明走向或全球格局：`cn--b221--p01` 秦灭六国成一统 w5、`cn--1045--s01` 毕昇作活字印版 w5、
  `world--1348--d01` 黑死病席卷欧洲 w5、`world--1789--p01` 法兰西革命 w5、`world--1945--p02` 德国无条件投降 w5、
  `world--1969--s01` 阿帕网首次主机间通信 w5
- **4** 深刻影响一个时代/大型政权：`cn--1861--i01` 设总理各国事务衙门 w4、`cn--1898--p01` 明定国是与百日新政 w4、
  `world--1519--x01` 麦哲伦启程 w4、`world--1993--s01` 万维网进入公共领域 w4
- **3** 重要区域性/领域内事件（一场决定性战役、一部经典成书、一次改革）：`cn--b684--m01` 长勺之战 w3、
  `cn--1371--i01` 洪武始开科举取士 w3
- **2** 局部或专门意义（一次会盟、一项次级发明、一部作品问世）：`cn--b2800--a01` 龙山蛋壳黑陶礼器 w2、
  `cn--1823--s01`《神天圣书》全译刊行 w2
- **1** 补充性细节、地方事件：`cn--b613--p01` 楚大饥，戎与群蛮叛楚 w1、`cn--b538--f01` 竖牛专鲁叔孙氏 w1

**例证只示意量级，一律以语料为准。** 本节此前写的是通俗例名而非 id，其中「印刷术」「洋务运动」在库里
根本没有同名条目、「均田制」列在 4 级而盘上 `cn--485--i01` 实为 5 级——照这样的例证推理必然得出与语料
相反的答案。故按 §4A② 全部换成可 grep、权重与盘上一致的 id，并由 `tools/doc-cite.mjs` 机器核账。

**缩放层级与权重的真实关系**（此前记述与 `js/lod.js` 相反）：`minWeight` 只在**单年层级**生效——
L2 把 weight < 4 的并入 `+N` 折叠、L1 全量显示。L5/L4/L3 是时代带与 50/10 年 bin 聚合，
**不做权重过滤**：整段事件并入一个 bin，bin 的强度取其中最高权重（`b.weight = max`）。
所以"缩小后只剩 5 级"是聚合的视觉效果，不是一条过滤规则。

**每个分片内 weight=5 的条数应占 8–15%**，weight≥4 占 25–35%。若你的分片里全是 5，说明标尺失效。

## 4A. 权重校准的三条实测结论（2026-09-22 复核补）

**① 目标带是参照，不是违规线。** §4 的 8–15% / 25–35% 复算 27 片后发现普遍未达：除 cn-07 外 w5 实测 0.0–11.9%、w≥4 实测 26.3–39.4%，14/27 片至少一项越带。若按目标带判违规，一开就是十几条噪声，噪声会淹掉真离群。故 `validate.mjs` 把两者分开命名：触发线（15% / 5% / 40%）判违规，目标带只在消息里附带报出。**任何门的文案不得声称一条带而代码执行另一条带**——此处曾是真实缺陷：`W5_LOW` 文案写"低于 8–15%"而触发线是 5%，cn-13 升到 6.35% 即静默通过。

**② §4 的例证表曾与语料实评互相矛盾，引用前必须先查语料。** 当时核实两处：

| 旧 §4 列为 4 级的例 | 语料实评 | 后果 |
|---|---|---|
| 均田制 | `cn--485--i01` = w5 | 以"均田制才 4"论证《土地改革法》降 4 → 前提落空，驳回 |
| 冷战开始 | `world--1947--p01 杜鲁门主义` = w5 | 以"不应高于母题"论证中苏条约降 4 → 前提落空，驳回 |

本轮已把 §4 五级例证全部替换为盘上真实 id（并删掉库里根本不存在的「印刷术」「洋务运动」两例），
且由 `tools/doc-cite.mjs` 把文档里每一处「id + wN」与语料逐条对账——**文档引用不再靠人自觉**。
机制性结论不变：照文档文本推理和照语料先例推理得出不同答案，本身就是标尺失效。
**复核一条权重时，"同级参照"必须给出可在语料里 grep 到的 id 与其当前值**，不能引 §4 例证表了事。
`tools/doc-cite.mjs` 把这条变成机检：**写出的 wN 与盘上不符即硬性错误**，引用没带级记告警（提示补成
「id 简述 wN」）。

**③ 同一因果链只许一个高分节点（此前未成文，本轮主要降权依据）。** 一条链上的纲领/会议/批准/统计结论若各给高分，是对同一结构变动的重复计分。口径：

- 承载实质后果的那一条拿高分，其纲领口号、其批准会议、其完成统计各降一级。
  例：一五计划链上 `cn--1953--e01`（开始执行，盘上 w4）留高分，`cn--1955--p06`（人大批准，盘上 w3）、
  `cn--1957--e01`（超额完成，盘上 w3）各停一级。
- **战役、会议节点、人物生卒、单项工程成就默认归 3**（§4 之 3 已明列"一场决定性战役"；
  生卒的默认级以本条为准，旧 §4 曾把"人物生卒"列为 1 级例证，与语料实测不符——91 条生死类 `figure`
  条目里 3 级最多（37 条）、2 级 30 条、1 级 18 条，另有个别大节点及 4/5，如 `cn--b479--f01` 孔子卒 w5）。
- **跨轨同一事件必须同级**，由 `validate.mjs` 的 `XTRACK_LEVEL` 执行。此条此前只是文字：
  中国 1967 氢弹曾在本轨评 5、他轨评 3（相差两级即为硬矛盾），本轮按"取中间偏低一级"校准为两轨同级：
  `cn--1967--s01` w4 与 `world--1967--s01` w4。
- 链上前提节点停一级、转折实节点拿高分——正例（盘上可核）：`cn--1971--p01` 基辛格秘密访华 w4 →
  `cn--1972--p01` 尼克松访华与《上海公报》w5。此惯例与③并存，**不得反过来用它论证"采纳节点永远低于
  原创节点"**，采纳若改变全球格局亦可及 5（`cn--1994--s01` 中国全功能接入互联网 w5，即按此升）。
  **反例裁定（2026-09-22，经 `tools/weight-change.mjs` 落盘）**：入世链曾倒挂——链首的申请节点比转折
  实节点高两级。现按③「实质后果落在转折实节点」与「跨轨同一事件必须同级」定为链上唯一高分：
  `world--2001--i03` w5 与同事件中国轨 `cn--2001--e01` w5 同级；申请与谈判节点 `cn--1986--e01` w3、
  `cn--1999--e01` w3 齐平，其后的 `cn--2002--e02` w3 不变。
  **此例暴露的门禁盲区已补**：`XTRACK_LEVEL` 的判据是「同年 + 归一化标题全同」，而这两条标题措辞不同
  （"成为…第143个成员" / "加入世界贸易组织"），门当时完全静默。现补一条只出告警的候选门
  `XTRACK_NEAR`：跨轨同年、权重不等、**汉字最长公共串 ≥6 字**即列为待裁定候选（阈值 6 是实测定的——
  ≥5 时「2024年经济」这类年份巧合会把无关对混进来）。真实候选 2 对，均已裁定为**两件事**并记入
  `validate.mjs` 的 `NEAR_EXEMPT`（豁免必须带理由，且由 `tools/test-gates.mjs` 的「删掉一条豁免即现形」
  用例验它承重）：`cn--1997--e01` w4 亚洲金融危机与人民币不贬值承诺 ↔ `world--1997--e01` w5 危机爆发；
  `cn--1984--c01` w3 中国代表团参加洛杉矶奥运会 ↔ `world--1984--p01` w2 苏联等国缺席同一届奥运。

**边界不清时保留原级。** 降权理由只能是"十年结构后果不成立"或"重复计分"，不得是题材敏感；两条都不明确时不降。本轮据此驳回 12 条降权建议。

## 5. 内容规则

- **一条一义**：一个 `id` 只承载一件事。禁止"某年发生 A、B、C"式合并条目。
- **一条只归一个 `dim`，重复录入由门禁处置。** id 编码了 dim 首字母，所以同一事件换第二个 dim 再录一次
  必然得到另一个 id——既有 `EVENT_DUP`（轨+年+维+题全同）因此**结构性看不见**跨维重复，本轮补两道门：
  `EVENT_DUP_DIM`（错误，同轨同年、归一化标题相同而 dim 不同）与 `XTRACK_LEVEL`（告警，跨轨同题不同级，
  即 §4A③ 那条同级要求的执行体）。处置工具 `tools/drop-dups.mjs`：先 `--plan` 出裁定表再 `--write`；
  裁定表里每个"同级参照"引用的 id 会被机器核到存在、且权重与盘上一致，对不上即拒绝执行——§4A② 的
  「参照必须可 grep」到这里才不再是靠人自觉。判据一律用归一化标题**完全相同**这一条机械口径；
  相似度召回留给审计脚本，不进门禁（门禁掺了误报，人就学会忽略它）。
- **只陈述事实与出处，不做价值排序**。涉及评价时用"据《X》载""学界认为"等归因表述。
- 中外关系、殖民、战争、灾害、1949 年后条目：**措辞严格中立、标注来源**，不写宣传语也不写反宣传语。
- 1949 年后条目正常纳入（政治、经济、科技、文化、灾害、外交均可），来源用官方公报、权威统计年鉴、主流通讯社与学术著作。
- 涉及争议年代（夏商周、神话时代、史前）必须 `yearApprox: true`。
- 同一年同一 `dim` 允许多条（用不同 slug 区分）。
- **禁止问号占位**。任何字段值内都不得出现 `汉字+?`，也不得出现两个及以上相邻问号（`？ ？`、`??`）。
  实测已有三名作者代理在记不准原句时用问号填充字位，产出的条目语法、schema、`related` 全绿，
  只有语义是空的——这种缺陷不会让任何解析报错，只能靠此禁令拦下（`validate.mjs` 的 `CORRUPT` 门）。
  不满足时的替代动作是**可达成的**，按优先级择一：①删去自己没把握的那个从句，句子短一点没关系；
  ②引文确实有缺字/异文，用「□」标注（沿用金石与典籍校勘的阙文体例），并把这个不确定写进 `sources`；
  ③整句无据则整条不写。**宁可少一条，不可有一条空的。**

## 5A. 语域（文体统一）

全库只有一种散文语域：**现代汉语骨架 + 文言省字法**（即浅近文言）。判据不是主观读感，
而是 `title + summary` 的**白话虚词密度**（虚词表 `了/的/是/在/被/把/从/对于/已经/进行`，
与 `tools/style-probe.mjs` 逐字相同，两处量出来的数才会一致）。2026-09-22 全库实测：

- 世界线 27 分片带：`0.2 – 3.4 / 百字`，中位约 `1.2`
- 中国线带：`0.1 – 1.2 / 百字`，中位约 `0.3`（年代越早越简，符合编年体本相）

**这条线是双向的**：白话填充是偏离，省到没有信息也是偏离。

### 已发生的事故（写在这里是为了不再犯）

`wd-04`（世界史 1500–1799）曾被整片改写成白话，密度 **5.5/百字**，是全库唯一离群值，
读者会觉得站点里同时有两本书。症状三条：①虚词填充（「全城的人几乎都失去了衣服」）；
②欧化语序（「被官家的火处死在日内瓦」——动词后挂地点是译音句法）；
③解释腔（「因为…的缘故」「就能」「于是」把史笔拉成讲义）。
2026-09-22 分四批做语域回正，171 条改写、8 条原样保留，密度降到 **0.2/百字**，
专名与数词锚零丢失。**教训：一次改写把离群值推到另一端的极值，仍算未统一**——
故本节的门是双向的，且回正后必须重读样本，不能只看指标。

`wd-01`（世界史 前3000→前479）现为 **3.4/百字**，是本节生效后的剩余离群值，待同样处理。

### 逐条替换表

| 现在（白话/欧化） | 改为（史笔） |
|---|---|
| `在+地点` 作状语：`在莱顿刊行` | `刊于莱顿` / `莱顿刊行` |
| 动词+`在+地点` 作补语：`处死在日内瓦` | `焚于日内瓦`、`死在` → `卒于` |
| 完成体 `了`：`打垮了它的苏丹` | `破其苏丹` |
| `…的缘故`：`因为反三位一体的缘故` | `以反三位一体触法` |
| 判断 `是`：`确定心脏是泵` | `定心为泵` |
| 领属 `的`：`全城的人` | `举城之人` |
| 被动 `被`：`被土人的长矛刺死` | `为土人长矛所刺` |
| `把`字句：`把各家的地图合成一册` | `合诸家地图为一册` |
| `就能 / 才能 / 于是 / 所以` | 删，或 `始`、`乃`、`遂` |
| `一个…的说法` | `…之说` |

不许走到另一极端：`之乎者也` 堆满、`寻/俄而/既而/会/适` 连用同样是偏离。
判准是「今人一读能懂」，不通假字、不用生僻字。

### 门禁与必跑命令

`validate.mjs` 里两条（对**每个非空分片**都算，小分片不豁免）：

- `REG_VERNAC`：密度 > `2.6` 警告，> `4.0` 错误。错误线就钉在 wd-04 事故当时的实测值上——
  用失败值本身做门，比凭空定的数更难被argue掉。
- `REG_THIN`：摘要均长 < 10 字警告。这是反向过矫（省到没信息）的信号。

任何语域改写必须按此顺序跑，且**先证明门能红再相信它绿**：

```
node tools/rewrite-invariants.mjs <before> <after>   # 事实字段必须逐字节未动
node tools/prose-anchor.mjs <before> <after>         # 数词/拉丁/「」/《》内容锚必须原样在场
node tools/gen-manifest.mjs                            # 改过 data/ 必跑：清单与实态不符会让站点静默漏片
node tools/validate.mjs --strict && node tools/test-units.mjs
node tools/weight-change.mjs <patch>                  # 改权重唯一入口，直接 Edit 分片里的 weight 会被 validate 判错
node tools/e2e-static.mjs                            # 动过 js/ 或脚本顺序时
node tools/test-gates.mjs && node tools/test-gates-meta.mjs && node tools/test-doc-cite.mjs   # 动过任何门的分支/阈值/正则时
node tools/doc-cite.mjs                              # 动过本文件或 README 里任何「id + 权重」引用时
node tools/related-candidates.mjs --min 4            # 补跨轨 related 的第一步：只出候选，不改盘
node tools/related-cross.mjs                         # dry-run 审计 tools/related-cross.json 的授权集
node tools/related-cross.mjs --write                 # 唯一授权的跨轨补边落盘（只追加，删边/改他字段即拒绝）
node tools/test-related-candidates.mjs               # 候选器判别力自审 + 候选集与裁定集双向对账
```

「先证明门能红再相信它绿」这条纪律现在有载体了：`tools/test-gates.mjs` 给每道门注入定向变异
并要求它变红命中指定检查码，`tools/test-gates-meta.mjs` 再把门改哑、验前者抓不抓到，
`tools/test-doc-cite.mjs` 则用**改输入**的方式验文档引用门（把文档里的 wN 写错、引用不存在的 id、
把权重推出窗口、抽走 README），逐条要求它变红并点名。
不必也不应靠临时往 `/tmp` 里写一次性脚本来证明——那种证明会随会话一起消失。

`prose-anchor.mjs` 存在的原因：`rewrite-invariants` 只冻结非散文字段，而**事实其实写在散文里**。
把「三十七人」写成「数十人」在字段级校验下全绿，那是造假，只能靠内容锚拦下。
独个「一」字不计为锚（它几乎全是不承载信息的量词冠），其余数词连同后一字一律硬保留。

## 6. `sources` 要求

至少 1 项，优先一手/权威：
- 中国先秦：《史记》《左传》《国语》《竹书纪年》《汉书》《资治通鉴》及现代考古报告
- 中国后世：《二十四史》相应史书、《续资治通鉴》、《明实录》、地方志、当代权威通史（如剑桥中国史分卷）
- 世界：对应文明的权威史著、剑桥/企鹅系列史、学界通行年表
- 当代：官方公报/白皮书、国家统计局年鉴、主流通讯社报道、同行评审研究
- 不写"维基百科"作为唯一来源；可写"据《XX 年鉴（20XX）》"

## 6A. 溯源四级：等级是算出来的，不是写出来的

界面、筛选、图例、并档裁定全都读同一个派生器 `js/prov.js`。`tierOf(e)` 的口径，逐条对应实现：

| 等级 | 判据 |
| --- | --- |
| `verified` 已核 | `checks` 里至少一条合式记录 |
| `locatable` 可定位 | 无合式核对记录，但 `sources` 命中任一**定位线索**：篇目／卷册（如「卷三九」「第三十九卷」）／节页（「第 112 页」「pp. 30-45」）／年月日／链接（`http(s)://`、`www.`、`ISBN`） |
| `titled` 仅书名 | `sources` 非空但一条定位线索都没有 |
| `unsourced` 无出处 | `sources` 为空 |

现库实测（2026-09-23，4900 条）：可定位 3388、仅书名 1512、已核 0、无出处 0。
「已核」为零不是漏配，是这套设计的起点——升档只能靠真实发生的核对累积。

**数据文件里写不出等级。**条目顶层一旦出现 `tier` / `prov` / `provenance` / `verified` /
`certified` / `confidence` / `badge` / `sourceTier` 任一字段，`validate.mjs` 报 `TIER_FIELD`
（硬性错误）。写等级=绕过派生器自封权威，这套标识就整层失效。

`checks[i]` 的合式判据（`validCheck` 与 `validate` 的 `CHECK_SHAPE` 同一个口径，
两处日期正则由 `test-units.mjs` 对账）：`by` 为非空字符串（**写清谁、翻的是哪一处**）、
`at` 严格为 `YYYY-MM-DD`、`note` 可选字符串。日期只收 ISO 是因为下游要按它排序与判过期，
写成「2026年9月」会被静默丢弃——投稿人填了核对记录、标签却毫无变化，就是这里。
`validate` 另有 `CHECK_WITHOUT_SOURCE` 告警：有核对记录却没有任何出处，「核对」失去对象。

### 对外投稿记录 `chronicle-contribution/1`

站方零后端，读者经 `js/contribute.js` 产出的是一条**记录**，不是数据文件。三种 kind：

```
{ schema:"chronicle-contribution/1", kind:"source"|"check"|"event", at:"YYYY-MM-DD",
  app:"时间长河", who?:署名, target?:"条目 id",
  locator?:"出处定位", note?:"补充说明", verdict?:"confirm"|"diverge"|"missing",
  event?: { id 由 id 规则另生成, year, yearApprox, track, dim, title, summary, sources[], weight: null } }
```

白名单之外的一律丢弃：投稿不带 `tier`／`weight`／`checks`／`related`／`id` 等任何自封字段
（`buildRecord` 白名单，`test-units.mjs` 逐字段注入探针验证带不进去）。`at` 恒为提交当日，
表单不接受外部传入的日期——否则谁都能把自己标成三年前核过。

记录到达作者手上的**唯一通道是 GitHub issue**：模板在 `.github/ISSUE_TEMPLATE/chronicle-contribution.md`，
正文留有 ```json 围栏。模板头的 `labels:` 与 `js/contribute.js` 的 `LABEL` 常量由
`test-units.mjs` 对账——不同源的话，投稿开出来就没有标签，通道等于悄悄断了。

并档时（README「数据维护」第 10 步）：`source.locator` 追加进 `detail.sources`、
`check` 转成 `checks[i] = {by: who + 定位, at, note}`、`event` 按 §2 新建且 **weight 由本站按 §4 重评**，
不采信投稿人给的任何重要度。

## 7. `id` 与 slug 规则

`{track}--{b?}{yearAbs}--{dimInitial}{seq}`

- track：`cn` 或 `world`
- year：写绝对值；**公元前必须加 `b` 中缀**，公元不加
  - `-636` → `cn--b636--pNN`　`1789` → `world--1789--pNN`（此处只示意拼法，seq 写作 NN）
  - 无 `b` 时 前1000 与 公元1000 会撞成同一个 `world--1000--cNN`，loader 只能把后到的改名，`related` 也会指错——这是硬性错误（`validate.mjs` 报 `ID_ERA`/`DUP_ID`）
- dimInitial 映射：p=politics, f=figure, s=science, c=culture, m=military, e=economy, i=institution, x=explore, d=disaster, a=art（`culture`/`c`、`art`/`a` 按此表）
- seq：两位数字，该年该维度内递增（01、02…）

**所有字段值必须是带引号的字符串或数组**。写成 `state: 明` 这种裸标识符，文件仍能通过 `node --check`，但整片在浏览器里求值时抛错，236 条一起消失（`validate.mjs` 报 `EVAL`）。

**用脚本生成时，落盘的必须是求值后的字符串**。实测事故：Python 生成器把 `related: ["cn--1778--cNN"] if False else q_placeholder` 整段表达式原样写进了 JS，整片解析失败（`validate.mjs` 报 `PY_LEAK`）。

**写文件必须显式 `encoding="utf-8"`**。实测事故：一次有损编码往返把「四大徽班进京」等条目的正文变成 `浙盐商? 金德? 辉? 等? 醵? 资?`——每丢一个字留一个 `?`，中文里合法的问号是全角「？」，因此半角 `?` 紧跟汉字即判为腐蚀（`validate.mjs` 报 `CORRUPT`，该条必须重写，无法机械修复）。

`related` 里可以引用**其他分片**的 id；若不确定对方 id，宁可不写 `related`，也不要编造（悬空引用是硬性错误）。跨分片关联的补全由主控统一处理。

## 8. 密度目标

分片需按年代给出可读密度：
- 公元前区间：重大世纪每世纪 15–40 条；只收 milestone 与关键战役/即位/发明
- 公元 1–1500：重要年份每年 1–4 条
- 1500–1840：每年 1–5 条
- 1840–1949：每年 2–8 条（中国侧重）
- 1949–2026：每年 3–10 条（双线都要密集）

不要为了凑数造事件；也不要遗漏本区间的公认里程碑。

## 9. 交付与落盘纪律（重要）

长任务必须**增量落盘**，禁止只在最后一次性写大文件：

1. 先 `Write` 建好文件骨架（注释头 + `window.__CHRONICLE_CHUNK["<id>"] = [` + `];`）。
2. 之后每次用 `Edit` 在 `];` 前追加 **一个年代段（约 30–60 条）**，分多次落盘。
3. 每追加一段后立刻 `node -e` 语法自检（见 §10），失败就地修复，不要继续堆。
4. 全部完成后做最终自检并把条数、维度分布、weight 分布回报给主控。

## 10. 自检命令

单分片快速自检（语法 + 逐条字段），只读一个文件，秒级返回：

```bash
node --input-type=module -e '
import fs from "fs"; global.window = {};
const f = "data/cn/cn-02.js";
const src = fs.readFileSync(f, "utf8");
new Function("window", src)(global.window);
const arr = global.window.__CHRONICLE_CHUNK["cn-02"];
const DIMS = ["politics","figure","science","culture","art","military","economy","institution","explore","disaster"];
let err = [];
const seen = new Set();
arr.forEach((e,i)=>{
  if (seen.has(e.id)) err.push("dup id "+e.id); seen.add(e.id);
  const m = /^(cn|world)--(b?)(\d+)--[pfscmeixad]\d\d$/.exec(e.id||"");
  if (!m) err.push("bad id shape "+e.id);
  else if (m[1]!==e.track) err.push("id track mismatch "+e.id);
  else if (Math.abs(e.year)!==+m[3] || (e.year<0)!==(m[2]==="b")) err.push("id year/era mismatch "+e.id+" year="+e.year);
  if (!Number.isInteger(e.year) || e.year===0) err.push("bad year "+e.id);
  if (!DIMS.includes(e.dim)) err.push("bad dim "+e.id+" "+e.dim);
  if (typeof e.weight!=="number"||e.weight<1||e.weight>5) err.push("bad weight "+e.id);
  if (!e.summary || [...e.summary].length>45) err.push("summary>45 "+e.id);
  if (!e.detail||!e.detail.process||!e.detail.sources||!e.detail.sources.length) err.push("detail incomplete "+e.id);
  (e.related||[]).forEach(r=>{ if(!r.startsWith("cn--")&&!r.startsWith("world--")) err.push("bad related "+e.id+" "+r); });
});
console.log("count",arr.length,"errs",err.length); err.slice(0,20).forEach(x=>console.log(" -",x));
'
```

`errs` 必须为 0。`related` 指向本分片外 id 的悬空检查由主控统一跑，你只需保证格式正确。

## 11. 全量门禁（改完数据最后要跑的）

分片自检只证明**这一个文件**语法与字段成立。落盘完成后必须跑全量：

```bash
node tools/gen-manifest.mjs        # 条数/年代/体积变了就要重算清单
node tools/validate.mjs --strict   # === ERRORS 必须为 0
node tools/test-units.mjs
node tools/e2e-static.mjs
node tools/test-gates.mjs
node tools/test-gates-meta.mjs
node tools/test-doc-cite.mjs
```

各门的触发条件见 `README.md`「数据维护」，判据与应达条数（各门后括注的「N 项」）见其「目录」一节，
此处不重复抄数：**同一个数字写在两处，就注定其中一处会腐烂**。提交或推送前再跑 `node tools/predeploy.mjs`
（工作树 + git 索引 clone 视图各验一遍）。

`test-doc-cite.mjs` 会读 `README.md` 与本文件：凡正文（非 ``` 围栏内）出现 `cn--…--xNN` / `world--…--xNN`
形式的 id 引用，都要核条目存在、且紧跟的 `wN`／「N 级」与盘上权重一致。所以**改了这两个文档就等于改了门禁输入**，
必须复跑该门；围栏内的占位一律写成双 `N`（`…--pNN`），它不匹配引用正则，不会被误当成真实条目。
