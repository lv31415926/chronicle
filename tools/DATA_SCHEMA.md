# 编年史数据分片编写契约（Data Authoring Contract）v1

所有数据分片必须严格遵守本文件。校验脚本 `tools/validate.mjs` 会按此判定错误。

## 1. 文件形态

零构建、`file://` 双击可运行 ⇒ **禁止 `export`/`import`/`fetch`**。每个分片是普通 `<script>` 文件，形态固定：

```js
/* chronicle data chunk: cn-02 | 春秋战国 前841–前221 | 生成于 2026-09-21 */
window.__CHRONICLE_CHUNK = window.__CHRONICLE_CHUNK || {};
window.__CHRONICLE_CHUNK["cn-02"] = [
  { /* event 1 */ },
  { /* event 2 */ }
];
```

- 文件必须是合法 JavaScript，能被 `node --input-type=module` 或直接 `node -e "require"` 方式加载（用 `global.window={}` 垫片）。
- 每条事件占**一行**（不换行），便于 diff 与定位。允许长行。
- UTF-8，中文不转义，不用 `\uXXXX`。
- 字符串内若需引号，用中文引号「」或“”，避免转义地狱。
- 单片体积上限 320KB（`validate.mjs` 的 `CHUNK_SIZE`，常量名 `MAX_CHUNK_BYTES`）——它是**性能预算**，
  不是内容指标。越线时的第一选项是拆分而不是删内容：`gen-manifest.mjs` 用文件名推出片 id，
  所以新片只要满足「文件名 = `__CHRONICLE_CHUNK` 的键」就能被接上，站外没有任何地方写死了片名。
  切点要选在史学分段上，不要选在字节数刚好够的地方。
  先例两则，都在 2026-11-07、都由 `cn-03` 越线触发、一条内容也没删：
  ①加四条后 336KB 越线，按**武帝即位**（前 141）把前 221–前 141 的 78 条迁出为 `cn-17`，
  原地留 168 条（前 139–59，实测值，不是标称区间）；此后 1f—1i 各批在这一段续到 186 条；
  ②批次1j 再加 12 条（186→198）后 351KB 越线，按**昭帝即位**（前 86）拆出 `cn-18`（前 86–59，118 条），
  原地留 80 条（前 139–前 87，即武帝一朝）——80+118=198 与拆前逐片计数守恒，拆分不删内容这条判据
  就是靠这样的加和对得上的。第②次拆完 `validate` 新报 `W4_HIGH`（`cn-03` w≥4 45.0%），
  这是分段把武帝朝的高权重挤到了一片，不是本次新增造成的失准，故登记为待裁定而不回改权重——
  拆分同时会重排警告带，所以切点选史学分段之后要回看 `W4_HIGH`/`W5_LOW` 有没有新触线。

## 2. 事件对象 schema

```js
{
  id: "cn--b636--pNN",
  track: "cn",                 // "cn" | "world"  —— 必须与 id 前缀一致
  year: -636,                  // 整数；公元前为负；不存在 0 年（-1 与 1 相邻）；范围 [-3000, 2026]
  yearApprox: false,           // 年代为学界推定/有争议 → true，界面显示 "~前2070年"
  dim: "politics",             // 见 §3 十维枚举，必须精确匹配
  weight: 4,                   // 1–5 整数，见 §4
  title: "晋文公即位",           // ≤ 24 字
  summary: "重耳结束十九年流亡归国为君，次年城濮之战称霸。",  // ≤ 45 字，悬停气泡用
  detail: {
    background: "……",           // 背景与缘起，1–3 句
    process: "……",              // 经过，2–5 句，含具体时间/地点/关键动作
    impact: "……",               // 影响与意义，1–3 句
    figures: ["重耳","狐偃","先轸"],   // 1–8 个关键人物，中文全名
    place: "晋（今山西翼城一带）",      // 地点，古今对照
    state: "晋国",                     // 政权/国家/文明，用于筛选与对照
    sources: ["《史记·晋世家》","《左传·僖公二十四年》"],  // ≥1 项，见 §6
    tags: ["春秋","霸主政治"]            // 2–5 个标签
  },
  // 下列两个 id 为占位示意（seq 写作 NN）；真实条目里 related 必须指向盘上存在的 id
  related: ["world--b636--pNN","cn--b632--mNN"],  // 0–4 项，必须指向真实存在的 id（禁悬空）
  checks: [ { by: "张三（翻中华书局点校本《史记》卷三九）", at: "2026-09-20", note: "原文作\"二年\"，条目误\"元年\"" } ]
  // 可选。核对记录：唯一能把溯源等级抬到「已核」的输入，见 §6A
}
```

字段全部**必填**（`related` 与 `checks` 可为空数组或整项省略）。不得新增未定义字段。

> **详情底部「此后」三格不是字段，也不要给它加字段。**「三年后／三十年后／这些人后来」全部由
> `js/detail.js` 按 `year` 与 `detail.figures` 现算（窗口表 `LATER_WINDOWS` 是唯一的年份口径，
> 界面与测试读同一份），刻意不读 `related`——跨轨 `related` 边只占 2.8%，靠它等于大多数条目
> 这一格永远空着。所以**编目时不要为了「让某条出现在另一条的三十年后」去改数据**：那种边一旦
> 手写就成了上面那句「不得新增未定义字段」所禁止的字段，而且它说的是因果，而这一格只承诺时间邻近——因果链是另一层
> 的事（要逐条带出处才敢写，尚未落 schema）。

## 3. 维度枚举（`dim`）

| key | 中文 | 口径 |
|---|---|---|
| `politics` | 国家政治 | 政权更迭、即位、篡夺、变法、外交会盟、统一与分裂、条约 |
| `figure` | 关键人物 | 核心人物的生卒、关键抉择、独立于事件的人格性节点 |
| `science` | 科技进步 | 发明、发现、工程、天文历法、医学、农具、算学、通信技术 |
| `culture` | 人文思想 | 哲学、宗教创立与传播、教育、学术范式、史学、思想论争 |
| `art` | 文学艺术 | 文学、音乐、绘画、雕塑、建筑作品、戏曲、书法 |
| `military` | 军事战争 | 战役、征服、军制改革、兵学著作、武器变革 |
| `economy` | 经济社会 | 贸易、货币、赋税、人口、城市化、民生、产业 |
| `institution` | 制度法律 | 官制、律令、科举/选官、土地制度、历法制度、行政建制 |
| `explore` | 地理探索 | 航行、地理发现、旅行记、疆域勘察、地图学 |
| `disaster` | 灾害疫情 | 灾荒、瘟疫、地震、洪水、气候事件及其社会后果 |

一条事件只归一个 `dim`（取其最主要面）。城濮之战归 `military`，晋文公称霸归 `politics`，二者用 `related` 连接。

## 4. `weight` 重要度判定

- **5** 改变文明走向或全球格局：`cn--b221--p01` 秦灭六国成一统 w5、`cn--1045--s01` 毕昇作活字印版 w5、
  `world--1348--d01` 黑死病席卷欧洲 w5、`world--1789--p01` 法兰西革命 w5、`world--1945--p02` 德国无条件投降 w5、
  `world--1969--s01` 阿帕网首次主机间通信 w5
- **4** 深刻影响一个时代/大型政权：`cn--1861--i01` 设总理各国事务衙门 w4、`cn--1898--p01` 明定国是与百日新政 w4、
  `world--1519--x01` 麦哲伦启程 w4、`world--1993--s01` 万维网进入公共领域 w4
- **3** 重要区域性/领域内事件（一场决定性战役、一部经典成书、一次改革）：`cn--b684--m01` 长勺之战 w3、
  `cn--1371--i01` 洪武始开科举取士 w3
- **2** 局部或专门意义（一次会盟、一项次级发明、一部作品问世）：`cn--b2800--a01` 龙山蛋壳黑陶礼器 w2、
  `cn--1823--s01`《神天圣书》全译刊行 w2
- **1** 补充性细节、地方事件：`cn--b613--p01` 楚大饥，戎与群蛮叛楚 w1、`cn--b538--f01` 竖牛专鲁叔孙氏 w1

**例证只示意量级，一律以语料为准。** 本节此前写的是通俗例名而非 id，其中「印刷术」「洋务运动」在库里
根本没有同名条目、「均田制」列在 4 级而盘上 `cn--485--i01` 实为 5 级——照这样的例证推理必然得出与语料
相反的答案。故按 §4A② 全部换成可 grep、权重与盘上一致的 id，并由 `tools/doc-cite.mjs` 机器核账。

**缩放层级与权重的真实关系**（此前记述与 `js/lod.js` 相反）：`minWeight` 只在**单年层级**生效——
L2 把 weight < 4 的并入 `+N` 折叠、L1 全量显示。L5/L4/L3 是时代带与 50/10 年 bin 聚合，
**不做权重过滤**：整段事件并入一个 bin，bin 的强度取其中最高权重（`b.weight = max`）。
所以"缩小后只剩 5 级"是聚合的视觉效果，不是一条过滤规则。

**每个分片内 weight=5 的条数应占 8–15%**，weight≥4 占 25–35%。若你的分片里全是 5，说明标尺失效。

## 4A. 权重校准的三条实测结论（2026-09-22 复核补）

**① 目标带是参照，不是违规线。** §4 的 8–15% / 25–35% 复算 27 片后发现普遍未达：除 cn-07 外 w5 实测 0.0–11.9%、w≥4 实测 26.3–39.4%，14/27 片至少一项越带。若按目标带判违规，一开就是十几条噪声，噪声会淹掉真离群。故 `validate.mjs` 把两者分开命名：触发线（15% / 5% / 40%）判违规，目标带只在消息里附带报出。**任何门的文案不得声称一条带而代码执行另一条带**——此处曾是真实缺陷：`W5_LOW` 文案写"低于 8–15%"而触发线是 5%，cn-13 升到 6.35% 即静默通过。

**② §4 的例证表曾与语料实评互相矛盾，引用前必须先查语料。** 当时核实两处：

| 旧 §4 列为 4 级的例 | 语料实评 | 后果 |
|---|---|---|
| 均田制 | `cn--485--i01` = w5 | 以"均田制才 4"论证《土地改革法》降 4 → 前提落空，驳回 |
| 冷战开始 | `world--1947--p01 杜鲁门主义` = w5 | 以"不应高于母题"论证中苏条约降 4 → 前提落空，驳回 |

本轮已把 §4 五级例证全部替换为盘上真实 id（并删掉库里根本不存在的「印刷术」「洋务运动」两例），
且由 `tools/doc-cite.mjs` 把文档里每一处「id + wN」与语料逐条对账——**文档引用不再靠人自觉**。
机制性结论不变：照文档文本推理和照语料先例推理得出不同答案，本身就是标尺失效。
**复核一条权重时，"同级参照"必须给出可在语料里 grep 到的 id 与其当前值**，不能引 §4 例证表了事。
`tools/doc-cite.mjs` 把这条变成机检：**写出的 wN 与盘上不符即硬性错误**，引用没带级记告警（提示补成
「id 简述 wN」）。

**③ 同一因果链只许一个高分节点（此前未成文，本轮主要降权依据）。** 一条链上的纲领/会议/批准/统计结论若各给高分，是对同一结构变动的重复计分。口径：

- 承载实质后果的那一条拿高分，其纲领口号、其批准会议、其完成统计各降一级。
  例：一五计划链上 `cn--1953--e01`（开始执行，盘上 w4）留高分，`cn--1955--p06`（人大批准，盘上 w3）、
  `cn--1957--e01`（超额完成，盘上 w3）各停一级。
- **战役、会议节点、人物生卒、单项工程成就默认归 3**（§4 之 3 已明列"一场决定性战役"；
  生卒的默认级以本条为准，旧 §4 曾把"人物生卒"列为 1 级例证，与语料实测不符——91 条生死类 `figure`
  条目里 3 级最多（37 条）、2 级 30 条、1 级 18 条，另有个别大节点及 4/5，如 `cn--b479--f01` 孔子卒 w5）。
- **跨轨同一事件必须同级**，由 `validate.mjs` 的 `XTRACK_LEVEL` 执行。此条此前只是文字：
  中国 1967 氢弹曾在本轨评 5、他轨评 3（相差两级即为硬矛盾），本轮按"取中间偏低一级"校准为两轨同级：
  `cn--1967--s01` w4 与 `world--1967--s01` w4。
- 链上前提节点停一级、转折实节点拿高分——正例（盘上可核）：`cn--1971--p01` 基辛格秘密访华 w4 →
  `cn--1972--p01` 尼克松访华与《上海公报》w5。此惯例与③并存，**不得反过来用它论证"采纳节点永远低于
  原创节点"**，采纳若改变全球格局亦可及 5（`cn--1994--s01` 中国全功能接入互联网 w5，即按此升）。
  **反例裁定（2026-09-22，经 `tools/weight-change.mjs` 落盘）**：入世链曾倒挂——链首的申请节点比转折
  实节点高两级。现按③「实质后果落在转折实节点」与「跨轨同一事件必须同级」定为链上唯一高分：
  `world--2001--i03` w5 与同事件中国轨 `cn--2001--e01` w5 同级；申请与谈判节点 `cn--1986--e01` w3、
  `cn--1999--e01` w3 齐平，其后的 `cn--2002--e02` w3 不变。
  **此例暴露的门禁盲区已补**：`XTRACK_LEVEL` 的判据是「同年 + 归一化标题全同」，而这两条标题措辞不同
  （"成为…第143个成员" / "加入世界贸易组织"），门当时完全静默。现补一条只出告警的候选门
  `XTRACK_NEAR`：跨轨同年、权重不等、**汉字最长公共串 ≥6 字**即列为待裁定候选（阈值 6 是实测定的——
  ≥5 时「2024年经济」这类年份巧合会把无关对混进来）。真实候选 2 对，均已裁定为**两件事**并记入
  `validate.mjs` 的 `NEAR_EXEMPT`（豁免必须带理由，且由 `tools/test-gates.mjs` 的「删掉一条豁免即现形」
  用例验它承重）：`cn--1997--e01` w4 亚洲金融危机与人民币不贬值承诺 ↔ `world--1997--e01` w5 危机爆发；
  `cn--1984--c01` w3 中国代表团参加洛杉矶奥运会 ↔ `world--1984--p01` w2 苏联等国缺席同一届奥运。

**边界不清时保留原级。** 降权理由只能是"十年结构后果不成立"或"重复计分"，不得是题材敏感；两条都不明确时不降。本轮据此驳回 12 条降权建议。

## 5. 内容规则

- **一条一义**：一个 `id` 只承载一件事。禁止"某年发生 A、B、C"式合并条目。
- **一条只归一个 `dim`，重复录入由门禁处置。** id 编码了 dim 首字母，所以同一事件换第二个 dim 再录一次
  必然得到另一个 id——既有 `EVENT_DUP`（轨+年+维+题全同）因此**结构性看不见**跨维重复，本轮补两道门：
  `EVENT_DUP_DIM`（错误，同轨同年、归一化标题相同而 dim 不同）与 `XTRACK_LEVEL`（告警，跨轨同题不同级，
  即 §4A③ 那条同级要求的执行体）。处置工具 `tools/drop-dups.mjs`：先 `--plan` 出裁定表再 `--write`；
  裁定表里每个"同级参照"引用的 id 会被机器核到存在、且权重与盘上一致，对不上即拒绝执行——§4A② 的
  「参照必须可 grep」到这里才不再是靠人自觉。判据一律用归一化标题**完全相同**这一条机械口径；
  相似度召回留给审计脚本，不进门禁（门禁掺了误报，人就学会忽略它）。
- **事实层只陈述事实与出处，不做价值排序**。涉及评价时用"据《X》载""学界认为"等归因表述。
  本站的编辑立场（取舍、突出、比较）**一律只写在视角层** `data/frame/highlights.js`，
  由 `tools/validate-frame.mjs` 校验；事实层不因立场而增删评价词——
  但评价词若漏进事实层的五个**叙述字段**（title/summary/background/process/impact），
  由 `tools/validate-achv.mjs` 的 `ACHV_STANCE` 判红，落在引号对内的文献原话豁免（§14A）。
  两层的分界见 §13，成就线的地基见 §14。
- 中外关系、殖民、战争、灾害、1949 年后条目：**措辞严格中立、标注来源**，不写宣传语也不写反宣传语。
- 1949 年后条目正常纳入（政治、经济、科技、文化、灾害、外交均可），来源用官方公报、权威统计年鉴、主流通讯社与学术著作。
- 涉及争议年代（夏商周、神话时代、史前）必须 `yearApprox: true`。
- 同一年同一 `dim` 允许多条（用不同 slug 区分）。
- **禁止问号占位**。任何字段值内都不得出现 `汉字+?`，也不得出现两个及以上相邻问号（`？ ？`、`??`）。
  实测已有三名作者代理在记不准原句时用问号填充字位，产出的条目语法、schema、`related` 全绿，
  只有语义是空的——这种缺陷不会让任何解析报错，只能靠此禁令拦下（`validate.mjs` 的 `CORRUPT` 门）。
  不满足时的替代动作是**可达成的**，按优先级择一：①删去自己没把握的那个从句，句子短一点没关系；
  ②引文确实有缺字/异文，用「□」标注（沿用金石与典籍校勘的阙文体例），并把这个不确定写进 `sources`；
  ③整句无据则整条不写。**宁可少一条，不可有一条空的。**
- **散文里的「（见 cn--xxxx）」同样是引用，两条门都管得到它。** `related` 数组的门
  （`RELATED_*`）只读数组，看不见写在 background/process/impact 里的内联引用；而读者照样点、
  照样按那句话换算年份。`validate.mjs` 因此另有两码：
  `XREF_DANGLING`（内联引用的 id 不在盘上——改名或删条目时正文没跟着改）与
  `REL_YEAR`（「明年／又明年／后 N 年／N 年后 + （见 id）」的年差算不回来）。
  `REL_YEAR` 的锚年＝同一句内该词之前最后一个「前 N 年／公元 N 年」，句内无明确纪年时取本条 `year`；
  `明年｜次年`＝+1、`又明年｜后年`＝+2、`后 N 年｜N 年后`＝+N。盘上三个叙述字段里 122 处内联 id 提及，
  其中 98 处写成「见」式（带括号 80 + 裸写 18），这两种都在扫描域内，`（见 a、b）` 的每个 id 逐个算；
  `checks[].note` 刻意不扫——核对记录里写的正是「本条旧 id 曾作某号、后改系某年」这类
  作废 id 的历史记述，扫它等于逼作者把改坏的证据删掉。
  2026-11-07 上线时，本批共有 12 条条目的年差写法被回改并逐处登记在 `checks[].note`
  （7 条由这对门现形——含「十九年后」误取苏武留匈奴年数、「三十年后」实为四十一年后；
  另外 5 条「明年」类是这对门动笔前一次性脚本扫出来的，正是它们证明了规则不进门下一批照错）。
  可红性证明在 `tools/test-gates.mjs` 五·乙（四条变异：断链、指错条目、多目标第二个 id、裸「见 id」），
  死门回捕在 `tools/test-gates-meta.mjs` 对应四条。12 这个数字可复算：逐片取 `checks[].note`
  含「本次回改」且句中出现「旧作／故以／故改／径书」与年差词者计数。

## 5A. 语域（文体统一）

全库只有一种散文语域：**现代汉语骨架 + 文言省字法**（即浅近文言）。判据不是主观读感，
而是 `title + summary` 的**白话虚词密度**（虚词表 `了/的/是/在/被/把/从/对于/已经/进行`，
与 `tools/style-probe.mjs` 逐字相同，两处量出来的数才会一致）。2026-09-22 全库实测：

- 世界线带：`0.2 – 3.4 / 百字`，中位约 `1.2`（分片数与片名以 `data/manifest.js` 现量为准，此处只记当日实测的密度带）
- 中国线带：`0.1 – 1.2 / 百字`，中位约 `0.3`（年代越早越简，符合编年体本相）

**这条线是双向的**：白话填充是偏离，省到没有信息也是偏离。

### 已发生的事故（写在这里是为了不再犯）

`wd-04`（世界史 1500–1799）曾被整片改写成白话，密度 **5.5/百字**，是全库唯一离群值，
读者会觉得站点里同时有两本书。症状三条：①虚词填充（「全城的人几乎都失去了衣服」）；
②欧化语序（「被官家的火处死在日内瓦」——动词后挂地点是译音句法）；
③解释腔（「因为…的缘故」「就能」「于是」把史笔拉成讲义）。
2026-09-22 分四批做语域回正，171 条改写、8 条原样保留，密度降到 **0.2/百字**，
专名与数词锚零丢失。**教训：一次改写把离群值推到另一端的极值，仍算未统一**——
故本节的门是双向的，且回正后必须重读样本，不能只看指标。

`wd-01`（世界史 前3000→前479）现为 **3.4/百字**，是本节生效后的剩余离群值，待同样处理。

### 逐条替换表

| 现在（白话/欧化） | 改为（史笔） |
|---|---|
| `在+地点` 作状语：`在莱顿刊行` | `刊于莱顿` / `莱顿刊行` |
| 动词+`在+地点` 作补语：`处死在日内瓦` | `焚于日内瓦`、`死在` → `卒于` |
| 完成体 `了`：`打垮了它的苏丹` | `破其苏丹` |
| `…的缘故`：`因为反三位一体的缘故` | `以反三位一体触法` |
| 判断 `是`：`确定心脏是泵` | `定心为泵` |
| 领属 `的`：`全城的人` | `举城之人` |
| 被动 `被`：`被土人的长矛刺死` | `为土人长矛所刺` |
| `把`字句：`把各家的地图合成一册` | `合诸家地图为一册` |
| `就能 / 才能 / 于是 / 所以` | 删，或 `始`、`乃`、`遂` |
| `一个…的说法` | `…之说` |

不许走到另一极端：`之乎者也` 堆满、`寻/俄而/既而/会/适` 连用同样是偏离。
判准是「今人一读能懂」，不通假字、不用生僻字。

### 门禁与必跑命令

`validate.mjs` 里两条（对**每个非空分片**都算，小分片不豁免）：

- `REG_VERNAC`：密度 > `2.6` 警告，> `4.0` 错误。错误线就钉在 wd-04 事故当时的实测值上——
  用失败值本身做门，比凭空定的数更难被argue掉。
- `REG_THIN`：摘要均长 < 10 字警告。这是反向过矫（省到没信息）的信号。

任何语域改写必须按此顺序跑，且**先证明门能红再相信它绿**：

```

node tools/prose-anchor.mjs <before> <after>         # 数词/拉丁/「」/《》内容锚必须原样在场
node tools/gen-manifest.mjs                            # 改过 data/ 必跑：清单与实态不符会让站点静默漏片

node tools/weight-change.mjs <patch>                  # 改权重唯一入口，直接 Edit 分片里的 weight 会被 validate 判错
node tools/weight-change.mjs <shard> <patch> --write  # 落盘；补丁文件本身要留在 tools/patches/ 里当授权记录
node tools/e2e-static.mjs                            # 动过 js/ 或脚本顺序时
node tools/test-gates.mjs && node tools/test-gates-meta.mjs && node tools/test-doc-cite.mjs   # 动过任何门的分支/阈值/正则时
node tools/doc-cite.mjs                              # 动过本文件或 README 里任何「id + 权重」引用时
node tools/related-candidates.mjs --min 4            # 补跨轨 related 的第一步：只出候选，不改盘
node tools/related-cross.mjs                         # dry-run 审计 tools/related-cross.json 的授权集
node tools/related-cross.mjs --write                 # 唯一授权的跨轨补边落盘（只追加，删边/改他字段即拒绝）
node tools/test-related-candidates.mjs               # 候选器判别力自审 + 候选集↔裁定集、盘上跨轨边↔accepted 双向对账（已在 GATES 内，每轮必跑）
```

「先证明门能红再相信它绿」这条纪律现在有载体了：`tools/test-gates.mjs` 给每道门注入定向变异
并要求它变红命中指定检查码，`tools/test-gates-meta.mjs` 再把门改哑、验前者抓不抓到，
`tools/test-doc-cite.mjs` 则用**改输入**的方式验文档引用门（把文档里的 wN 写错、引用不存在的 id、
把权重推出窗口、抽走 README），逐条要求它变红并点名。
不必也不应靠临时往 `/tmp` 里写一次性脚本来证明——那种证明会随会话一起消失。

`prose-anchor.mjs` 存在的原因：`rewrite-invariants` 只冻结非散文字段，而**事实其实写在散文里**。
把「三十七人」写成「数十人」在字段级校验下全绿，那是造假，只能靠内容锚拦下。
独个「一」字不计为锚（它几乎全是不承载信息的量词冠），其余数词连同后一字一律硬保留。

## 6A. 溯源四级：等级是算出来的，不是写出来的

界面、筛选、图例、并档裁定全都读同一个派生器 `js/prov.js`。`tierOf(e)` 的口径，逐条对应实现：

| 等级 | 判据 |
| --- | --- |
| `verified` 已核 | `checks` 里至少一条合式记录，且该记录的 `by` 写明核在哪一处（见下） |
| `locatable` 可定位 | 无合式核对记录，但 `sources` 命中任一**定位线索**：篇目／卷册（如「卷三九」「第三十九卷」）／节页（「第 112 页」「pp. 30-45」）／年月日／著录编号（「《甲骨文合集》6412、6413」「《历史》1.96」「《形而上学》983b」「878 条」「《文物》1975年第11期」）／链接（`http(s)://`、`www.`、`ISBN`）。著录编号这一类专门防年份冒充：「1912—1913年」「1880至1895年」「1818/1831年版」一类年跨度六类全不命中，完整年月日才走「年月日」那一档 |
| `titled` 仅书名 | `sources` 非空但一条定位线索都没有 |
| `unsourced` 无出处 | `sources` 为空 |

四级的读数**不在本文抄一份**，现算：`node tools/prov-stats.mjs --era`（判据就是 `js/prov.js` 本身，
不是第二把尺子）。手抄过一次就注定腐烂——这里曾经写着「可定位 3388／仅书名 1512」，
而库里早已是另一个数。分段读数能直接指出该先补哪一段：`仅书名` 占比最高的年代就是读者最查不到的地方。

**数据文件里写不出等级。**条目顶层一旦出现 `tier` / `prov` / `provenance` / `verified` /
`certified` / `confidence` / `badge` / `sourceTier` 任一字段，`validate.mjs` 报 `TIER_FIELD`
（硬性错误）。写等级=绕过派生器自封权威，这套标识就整层失效。

`checks[i]` 的合式判据（`validCheck` 与 `validate` 的 `CHECK_SHAPE` 同一个口径，
两处日期正则由 `test-units.mjs` 对账）：`by` 为非空字符串、
`at` 严格为 `YYYY-MM-DD`、`note` 可选字符串。日期只收 ISO 是因为下游要按它排序与判过期，
写成「2026年9月」会被静默丢弃——投稿人填了核对记录、标签却毫无变化，就是这里。

`by` 光非空不够：它必须**写明核在哪一处**。`validate` 对此报 `CHECK_BY_LOCATOR`（硬性错误），
尺子与 `js/prov.js` 的 `CHECK_KINDS` 同源——就是上面那六类定位线索，但**去掉「日期」这一类**：
「何时」已由 `at` 负责，让日期冒充位置，`张三（2026年9月20日核过）` 就能自封一档。
两套尺子的样例串（条数以 `tools/test-units.mjs` 运行时打印为准，不在这里抄死）双向对账，改一边就红；
`著录编号` 正反样本都在里面——`《甲骨文合集》6412、6413`、`《文物》1975年第11期` 要放行，`《申报》1912—1913年原载`、`《文物》1975年` 要拦住。

本站自己填的记录走的是**工具核对**这条路，`by` 形如
`本站·维基文库比对（史记/卷001 三家注版）`：说清用什么文本、对的是哪一卷。
「已核」的语义因此是「这段记述与它所引的那一处出处相符」，不是「这段历史被证明了」——
`explain()` 末句固定写着这条限定，任何抬档动作都绕不过它。

`validate` 另有 `CHECK_WITHOUT_SOURCE` 告警：有核对记录却没有任何出处，「核对」失去对象。

### 对外投稿记录 `chronicle-contribution/1`

站方零后端，读者经 `js/contribute.js` 产出的是一条**记录**，不是数据文件。三种 kind：

```
{ schema:"chronicle-contribution/1", kind:"source"|"check"|"event", at:"YYYY-MM-DD",
  app:"时间长河", who?:署名, target?:"条目 id",
  locator?:"出处定位", note?:"补充说明", verdict?:"confirm"|"diverge"|"missing",

白名单之外的一律丢弃：投稿不带 `tier`／`weight`／`checks`／`related`／`id` 等任何自封字段

## 7. `id` 与 slug 规则

`{track}--{b?}{yearAbs}--{dimInitial}{seq}`

- track：`cn` 或 `world`
- year：写绝对值；**公元前必须加 `b` 中缀**，公元不加
  - `-636` → `cn--b636--pNN`　`1789` → `world--1789--pNN`（此处只示意拼法，seq 写作 NN）
  - 无 `b` 时 前1000 与 公元1000 会撞成同一个 `world--1000--cNN`，loader 只能把后到的改名，`related` 也会指错——这是硬性错误（`validate.mjs` 报 `ID_ERA`/`DUP_ID`）
- dimInitial 映射：p=politics, f=figure, s=science, c=culture, m=military, e=economy, i=institution, x=explore, d=disaster, a=art（`culture`/`c`、`art`/`a` 按此表）
- seq：两位数字，该年该维度内递增（01、02…）

**所有字段值必须是带引号的字符串或数组**。写成 `state: 明` 这种裸标识符，文件仍能通过 `node --check`，但整片在浏览器里求值时抛错，236 条一起消失（`validate.mjs` 报 `EVAL`）。

**用脚本生成时，落盘的必须是求值后的字符串**。实测事故：Python 生成器把 `related: ["cn--1778--cNN"] if False else q_placeholder` 整段表达式原样写进了 JS，整片解析失败（`validate.mjs` 报 `PY_LEAK`）。

**写文件必须显式 `encoding="utf-8"`**。实测事故：一次有损编码往返把「四大徽班进京」等条目的正文变成 `浙盐商? 金德? 辉? 等? 醵? 资?`——每丢一个字留一个 `?`，中文里合法的问号是全角「？」，因此半角 `?` 紧跟汉字即判为腐蚀（`validate.mjs` 报 `CORRUPT`，该条必须重写，无法机械修复）。

`related` 里可以引用**其他分片**的 id；若不确定对方 id，宁可不写 `related`，也不要编造（悬空引用是硬性错误）。跨分片关联的补全由主控统一处理。

## 8. 密度目标

分片需按年代给出可读密度：
- 公元前区间：重大世纪每世纪 15–40 条；只收 milestone 与关键战役/即位/发明
- 公元 1–1500：重要年份每年 1–4 条
- 1500–1840：每年 1–5 条
- 1840–1949：每年 2–8 条（中国侧重）
- 1949–2026：每年 3–10 条（双线都要密集）

不要为了凑数造事件；也不要遗漏本区间的公认里程碑。

## 9. 交付与落盘纪律（重要）

长任务必须**增量落盘**，禁止只在最后一次性写大文件：

1. 先 `Write` 建好文件骨架（注释头 + `window.__CHRONICLE_CHUNK["<id>"] = [` + `];`）。
2. 之后每次用 `Edit` 在 `];` 前追加 **一个年代段（约 30–60 条）**，分多次落盘。
3. 每追加一段后立刻 `node -e` 语法自检（见 §10），失败就地修复，不要继续堆。
4. 全部完成后做最终自检并把条数、维度分布、weight 分布回报给主控。

## 10. 自检命令

单分片快速自检（语法 + 逐条字段），只读一个文件，秒级返回：

```bash
node --input-type=module -e '
import fs from "fs"; global.window = {};
const f = "data/cn/cn-02.js";
const src = fs.readFileSync(f, "utf8");
new Function("window", src)(global.window);
const arr = global.window.__CHRONICLE_CHUNK["cn-02"];
const DIMS = ["politics","figure","science","culture","art","military","economy","institution","explore","disaster"];
let err = [];
const seen = new Set();
arr.forEach((e,i)=>{
  if (seen.has(e.id)) err.push("dup id "+e.id); seen.add(e.id);
  const m = /^(cn|world)--(b?)(\d+)--[pfscmeixad]\d\d$/.exec(e.id||"");
  if (!m) err.push("bad id shape "+e.id);
  else if (m[1]!==e.track) err.push("id track mismatch "+e.id);
  else if (Math.abs(e.year)!==+m[3] || (e.year<0)!==(m[2]==="b")) err.push("id year/era mismatch "+e.id+" year="+e.year);
  if (!Number.isInteger(e.year) || e.year===0) err.push("bad year "+e.id);
  if (!DIMS.includes(e.dim)) err.push("bad dim "+e.id+" "+e.dim);
  if (typeof e.weight!=="number"||e.weight<1||e.weight>5) err.push("bad weight "+e.id);
  if (!e.summary || [...e.summary].length>45) err.push("summary>45 "+e.id);
  if (!e.detail||!e.detail.process||!e.detail.sources||!e.detail.sources.length) err.push("detail incomplete "+e.id);
  (e.related||[]).forEach(r=>{ if(!r.startsWith("cn--")&&!r.startsWith("world--")) err.push("bad related "+e.id+" "+r); });
});
console.log("count",arr.length,"errs",err.length); err.slice(0,20).forEach(x=>console.log(" -",x));
'
```

`errs` 必须为 0。`related` 指向本分片外 id 的悬空检查由主控统一跑，你只需保证格式正确。

node tools/date-candidates.mjs --apply && node tools/validate-dates.mjs && node tools/test-dates.mjs # 动过任何分片正文里那句「X年Y月Z日」
```

各门的触发条件见 `README.md`「数据维护」，判据与应达条数（各门后括注的「N 项」）见其「目录」一节，
此处不重复抄数：**同一个数字写在两处，就注定其中一处会腐烂**。提交或推送前再跑 `node tools/predeploy.mjs`
（工作树 + git 索引 clone 视图各验一遍）。

`test-doc-cite.mjs` 会读 `README.md` 与本文件：凡正文（非 ``` 围栏内）出现 `cn--…--xNN` / `world--…--xNN`
形式的 id 引用，都要核条目存在、且紧跟的 `wN`／「N 级」与盘上权重一致。所以**改了这两个文档就等于改了门禁输入**，
必须复跑该门；围栏内的占位一律写成双 `N`（`…--pNN`），它不匹配引用正则，不会被误当成真实条目。


## 12. 地理层契约（叠加层，不是事件 schema 的一部分）

事件对象**没有** `geo` 字段，也不会有。地理信息是一条叠加层：条目 id → 地名 key。
这样切的原因：4910 条逐条手填坐标一定烂尾，而且改了 `detail.place` 忘了改坐标时，
两边会各说一套。现在坐标只有一条来源——`detail.place` 里的「今X」对地名表做最长命中。

```
tools/geo-places.tbl   地名表源文件，8 列同构：key|古称|kind|今地|经度,纬度|命中词|说明|出处
                       改地名只动这里 → node tools/gen-places.mjs → data/geo/places.js
data/geo/places.js     生成物，勿手改
data/geo/event-places.js 生成物：{"cn--b221--p01": {p:"xianyang", d:"ne"}}
                       d 是语料写明的方位（今陕西咸阳东北），渲染时按固定表偏移，这里只存语义
tools/geo-water.tbl    水系与湖泊，含 appear/vanish（黄河夺淮 1128—1855、罗布泊干涸）
data/geo/journeys.js   作者策展的人物行迹（唯一手写件）
data/geo/snapshots.js  「山河大势」示意（作者自绘墨面，唯一手写件）
```

### 12A 命中口径（唯一实现在 `tools/geo-lib.mjs`）

取 `detail.place` 里「今」后面的宾语，在地名表的命中词里做**最长子串**匹配；
同长时点位优先于区域。所以「陕西西安西北」→ 西安（方位 nw），
「湖北荆州西北纪南城」→ 纪南城（比「荆州」长，命中楚都而不是今市）。
没有「今X」的条目再拿整串走同一条匹配兜底——全库只有 2036 条写了「今」，
只按前者判会把覆盖率天花板卡在 41%，看起来像「表不够全」。

候选器 / 落盘器 / 校验器共用这一份实现。**任何一侧另写一遍匹配规则，
三处就会量出三个覆盖率**，本项目在权重门上踩过同构的坑。

### 12B 手写件的两条硬规则

- **行迹**：每一站要么挂真实条目 id（`ev`），要么自带 `src` 出处；两者都没有 → `JOURNEY_NOSRC` 判红。
  站点年份必须单调不减，`span` 必须覆盖全部站点，少于 4 站不叫行迹。
- **大势快照**：必须有 `source`（依据）与 `license`（几何由谁绘、怎么许可），
  挂的事件 id 必须存在，面环必须闭合且 ≥4 点。缺任一条 → `SNAP_SCHEMA` / `SNAP_EVENT` 判红。

### 12C 不许出现在地理层里的东西

`tier` / `prov` / `provenance` / `verified` / `certified` / `confidence` / `badge` / `sourceTier` /
`weight` 这些字段名一旦出现在叠加层条目上，`OVERLAY_TIER` 判红——地理层不决定等级与权重，
等级只由 `js/prov.js` 对 `sources`/`checks` 现算。

### 12D 许可与合规

- 陆界：Natural Earth 1:110m（公有领域），经 `world-atlas` 的 TopoJSON 打包（ISC，仅构建期使用）。
- 水系、大势墨面：作者自绘示意，产物内逐项登记 `licenses` 与「非测绘成果」免责。
- 地名识别参考谭其骧主编《中国历史地图集》：只取「某古城即今某地」这类**结论（事实）**，
  未复制该书的**图幅、边界线与编绘成果（表达）**。
- 底图**不含现代国界与省界**。公开上线含边界的地图在境内可能触发地图审核/互联网地图服务合规，
  这不是代码问题，是发布资质问题；境内接入前先看 README「上线为公开站点 · 方案 B」。

### 12E 必跑

```bash
node tools/gen-places.mjs && node tools/gen-basemap.mjs
node tools/geo-apply.mjs --write
node tools/validate-geo.mjs && node tools/test-geo.mjs
node tools/geo-candidates.mjs --top 30     # 只读：还缺哪些地名
node tools/gen-topics.mjs                  # 静态专题页与 sitemap（换域名传 --base）
```

`OVERLAY_SYNC` 会把「表 + 语料」重算一遍并与盘上叠加层逐字比对：改了某条的 `detail.place`
却忘了重跑 `geo-apply`，红在这里，而不是等读者发现一条「今西安」的条目没落在西安。


## 13. 视角层契约（本站唯一允许写立场与比较的地方）

事实层（`data/{cn,wd}`）保持中立。取舍、突出、中外比较全部集中在
`data/frame/highlights.js`，它是一条**叠加层**：只引用条目，不修改条目。

```js
{ id: "cn--132--s01",                       // 必须是被引用的真实条目
  why: "用器物效验代替灾异遣告……",            // 本站的话：为什么值得看
  claim: {
    text: "世界最早的地震仪器记载",            // 本站主张（立场，不是史料）
    ground: "这是世界最早的地震仪器记载",      // ← 必须是该条目正文里逐字出现过的一段
    basis: "以文献记载与可复原机制为准",       // 判据：拿什么算「最早」
    scope: "全球",                            // 范围：跟谁比
    strength: "确证|通行说法|有争议",          // 强度
    dispute: "《后汉书》记载简略，复原方案诸家不一"  // 非「确证」必填
  },
  peer: { id: "world--132--p01", relation: "同期|先行|后继", note: "并置说明" } }
```

### 13A 五条硬判据（`tools/validate-frame.mjs`）

| 码 | 判什么 | 为什么 |
| --- | --- | --- |
| `FRAME_GROUND` | `claim.ground` 必须逐字出现在该条目的 summary/background/process/impact 里 | **反造神主判据**：立场只能复述史料说过的话，不能替史料说话 |
| `FRAME_SUPERLATIVE` | 出现「最早/第一/首次/领先/之最/唯一/最大/最完」就必须有 `basis`+`scope`+`strength` | 极限词是争议最集中处，缺判据就无法被检验 |
| `FRAME_DISPUTE` | `strength` 不是「确证」就必须写 `dispute`（≥8 字） | 读者先于你找到反例时，被连累的是全部看点 |
| `FRAME_PROV` | 被用来立论的条目，溯源必须 ≥「可定位」 | 「仅书名」的材料撑不起成就主张 |
| `FRAME_PEER` | 对照侧 id 必须存在；标「同期」两侧年差 ≤160 年 | 跨千年却写「同期」是最容易混过去的夸大 |

`FRAME_EMPTY`/`FRAME_STANCE` 另保两条底线：看点不能是空壳、立场必须自报是立场。
`tools/test-frame.mjs` 给每条判据都备了定向变异——包括「把『记载』写成『记录』」
这种一字之差，以及「把 A 条的原文当作 B 条的依据」。

### 13B 视角层与事实层的关系

- 视角层**不改**权重、不改文案、不改维度。想提高某项成就的可见度，只有两条正路：
  ① 把它写进看点（视角层，附原文与争议）；② 给它补出处与权重（事实层，走 `weight-change.mjs` 与 §4 标尺）。
- 看点引用的条目若溯源掉到「仅书名」，该看点即判红——**先补出处，再谈成就**。
  本轮实测就毙掉了 3 条（甲骨卜辞、曾侯乙编钟、青台丝织），原因全部是出处只到书名。
- `FRAME_PROV` 现在只判**立论侧**：`peer` 那一侧的溯源即使只是「仅书名」，门照样绿。
  这是尚未收的口，不是判据的边界——并置句不替对方下断言，所以暂不拦。
  真要收口，顺序不能反：先把对照侧条目的出处补到可定位（**真**页码／**真**图版号，不许造），
  再把判据扩到 `h.peer.id`；反过来做等于把门焊死在现有缺陷上，从此永远只能豁免。
- 上面这两条正路走完之后，成就的**地基本身**由 §14 的成就线门看着；
  视角层不检查事实层有没有退化，那是 `validate-achv.mjs` 的职责。

## 14. 成就线契约（立场踩的那块地基本身也要有人看着）

视角层可以选它要突出的东西，但它引用的东西住在事实层与 `data/themes.js` 里。
本节把「成就补齐」从一次性的补条目劳动，变成一条不会静默退化的门：
线还在不在、成员够不够、锚点的出处能不能翻、评价词有没有漏进叙述句。

### 14A 四条判据（`tools/validate-achv.mjs`）

| 码 | 判什么 | 为什么 |
| --- | --- | --- |
| `ACHV_LINE` | 九条成就线（青铜礼乐 / 丝绸瓷器 / 水利 / 历法算学 / 医与农 / 选官 / 书画 / 荒政常平 / 航海市舶）必须仍存在于 `data/themes.js` | 线被删或被改名，读者就点不到它，而 `validate.mjs` 只看分片字段，看不见主题层 |
| `ACHV_GAP` | 每条线成员 ≥15、其中 w≥4 ≥2、w≥3 ≥10、中国侧 ≥5 | 只剩过程流水、没有高光条目的「成就线」，等于把这个位置让给别国的故事 |
| `ACHV_PROV_RATCHET` | 成就维（science / culture / art / institution / explore / economy）里 w≥4 却只写到书名的条数 ≤ 基线 | 棘轮，只许降不许升：抬权重而不补出处，等于把「查不到东西」的条目摆上高光位置 |
| `ACHV_STANCE` | 评价词（辉煌 / 灿烂 / 骄傲 / 自豪 / 瑰宝 / 举世瞩目 / 博大精深 / 遥遥领先 / 壮举 / 无双 / 伟大 / 光荣）不得出现在 title、summary、background、process、impact 的**引号对之外** | 立场写进叙述句就是替史料说话；文献原话加引号即可，加不了引号的就归视角层写 |

三条**豁免边界**同样有用例钉住（`tools/test-achv.mjs` 里的 mustGreen）：
引号对内的原文评价词不红；`tags`/`sources`/`figures`/`place`/`state` 整域不扫——
专名「吴伟业」「光荣之革命」落在这些字段里是正当的，误报救不回来，只会教人来忽略这道门；
非成就线塌方不牵连成就门。
词表里刻意不含「伟业」：它是明末作者吴伟业的本名，写进 background 就是误报，
删词并写明理由，而不是往门里加特例豁免。

### 14B 成员怎么算：这里唯一的真风险

门**不复用** `js/themes.js`，而是复刻它的评分口径（关键词命中 hay +2、命中标题 +3、
命中标签 +2，到 `minScore` 起线；同年同维只留分最高的一条）。
好处是夹具能在几十条合成语料上把每个阈值精确打中；
代价是**没有编译期耦合**：改了 `js/themes.js` 的 `resolve()` 而忘了同步这里，
界面算出的成员集与门算出的会各说各话，而且两边都绿。
两个函数（`js/themes.js` 的 `resolve` 与 `tools/validate-achv.mjs` 的 `resolve`）
现在各自在注释里指名对方，改动必须成对发生。

计数一律用**截断前**的成员集：`max` 是给版面用的显示上限，不该拿它衡量语料到底有没有货。

### 14C 基线与下限都会过期，引用前先复算

`ACHV_PROV_RATCHET` 的基线、`ACHV_GAP` 的四条下限，都是某一天的实测快照，
它们只回答「有没有变得更差」，不回答「够不够好」——棘轮的方向是 0。
本文件因此**不抄写这些数字**（§11 早就立了这条规矩：同一个数字写在两处，就注定其中一处会腐烂）；
想知道当前读数，直接跑 `node tools/validate-achv.mjs`，它会把九条线的成员/锚点/中国侧逐行打出来。

### 14D 必跑

```bash
node tools/validate-achv.mjs          # 门：删条目、改主题线关键词或年代窗、改权重、改叙述字段文案之后
node tools/test-achv.mjs              # 门能红：四个码各被定向打红一次，三条豁免边界各判绿一次
node tools/geo-apply.mjs --write      # 新增条目带 detail.place 时，叠加层必须重算，否则 OVERLAY_SYNC 红
```

（成就线不进 `gen-topics.mjs`：专题页只摊地点、时代、行迹与看点，主题成员是运行时按关键词现算的。）

## 15. 故事层契约（`data/story/`：小故事、人物故事、朝代趣事）

### 15A 为什么它必须与事实层物理分开

事实层的条目来自书：出处写错了，指得回原书去对。故事层的 `scene` 是本站**自己写的白话复述**——
一句「他临死说」写歪了，读者翻遍史料也找不到那句话，而且再也追不回是谁在哪一版里改的。
所以这一层不能靠人工审完（审得完一批，审不完后来追加的那一批），也不能塞进事实层：
`tools/geo-lib.mjs` 的 `loadCorpus()` 只读 `data/cn` + `data/wd`，故事走独立全局
`window.__CHRONICLE_STORY_CHUNK`，于是加故事**不会**抬语料条数、不会动权重分布、
不会碰成就线棘轮的基线。这是刻意的隔离，不是遗留。

### 15B 一条故事的形状

```js
{ id: "st-han-007",            // /^st-[a-z][a-z0-9]*-\d{3}$/，前缀是分片名
  ev: "cn--b119--p01",         // 必须是 data/cn·data/wd 里真有的条目 id
  kind: "史载",                 // 四选一：史载 / 笔记异闻 / 后世附会 / 出土文献与档案
  title: "……",                 // ≤40 字
  people: ["霍光", "刘贺"],     // 非空；只放人，地点/机构/书名不算人
  scene: "……",                 // 本站的白话复述，不替史料说话，不写评价词
  quote: "……", quoteState: "verbatim" | "paraphrase",   // 可整对省略
  src: ["《汉书·霍光传》"],      // 非空；标 verbatim 时必须至少一条能定位
  caveat: "……",                // 笔记异闻／后世附会必填；每条极值语必填
  find: "……" }                 // 出土文献与档案必填（东西在哪个遗址/馆藏）
```

**不许出现** `year` / `era` / `dynasty` / `date` / `weight`。年份与朝代一律由 `ev` 锚点派生：
存一份就有第二份，两份打架时没人知道该信哪个；而条目改了系年，故事里那份会静默留在原地。

### 15C `kind` 四选一不是四档贬义

`后世附会` 不是骂人——它在流传里成形，照样值得看，只是不能当史料用。真正被禁止的是**只有一种 kind**：
全层 90% 以上标 `史载` 判红（`STORY_KIND` 分布哨兵），那等于本层没做过任何史料学判断。
`笔记异闻`／`后世附会` 必须自带一句 `caveat` 说明「既然不是史载，为什么还值得看」——
没有这句话，读者只会把它当成编的，而这一层的存在感就没了。

### 15D 「原文」两个字是这一层的信用总额

`quoteState: "verbatim"` 才允许在界面上显示「原文」，且 `src` 必须给到**能直接翻到的位置**。
定位判据六类。这份判据在仓里有**三处副本**（`js/prov.js` 的 `KINDS`、`tools/validate.mjs` 的
`CHECK_BY_LOC_RE`、`tools/validate-story.mjs` 的 `LOCATORS`）——浏览器文件不能 import 工具、
工具不能 require 浏览器，只能各留一份再逐串对账：`tools/test-units.mjs` 管前两份，
`tools/test-story.mjs` 管第一份与第三份；`tools/test-gates-meta.mjs` 给每一份的每一支都配上
能真红的哨兵（条数由它自己运行时打印，不在这里抄死），
改哑任何一处都会当场点名。判据形态：篇目 `《X·Y》`、卷册 `卷三/第3部`、节页 `第2节 / :12—18 / p.40`、
日期 `2026年1月5日`、著录编号 `《甲骨文合集》6412、6413` / `《历史》1.96` / `983b` / `878 条` / `《文物》1975年第11期`、
链接或 ISBN。

两个反复踩到的坑：

- **书名号里有中间点才算篇目**。《海国图志·原叙》可定位，《海国图志》只到书名 ⇒ 不可定位。
- **中国传统的纪年不满足日期判据**。「光绪二十七年正月」过不了 `\d{3,4}年\d{1,2}月\d{1,2}日`。
- **年跨度不是著录编号**。「《申报》1912—1913年原载」「1880至1895年」「1818/1831年版」都是出版年，
  不是能翻到的位置。`numbered` 的六个分支因此各带反向闸门，`tools/test-units.mjs` 正反样本都在表里。
  当年踩的坑是「可选组 + 前视」：`\d+(?:[、.]\d+)*` 后面跟 `(?![\d.])` 时，正则回溯到只吃一段数字，
  闸门照样放行——判据看起来收紧了，实测却一条没拦住。
- **「年第N期」是位置，「年」和「第N期」各自都不是**。《文物》1975年第11期 指得回那一本；
  只写 1975 年，一年二十几期无从指认；只写第 5 期，期号年年复用。这一支补的是仓里已在的
  发掘简报与评论引法（`tools/test-units.mjs` 的 `NUM_YES`／`NUM_NO` 两侧同时钉着），
  三份副本各配一条只删这一支的哨兵，改哑任何一份都会当场点名。
  所以拿不准是不是逐字、或只有一句流传本而没有可指位置的，**一律 `paraphrase`**，界面显示「大意」。
  宁可少标十个「原文」，不能错标一个——错标一个，读者就会把整层当成编的。

`quote` 与 `quoteState` 必须成对（有引无态、有态无引都红 `STORY_QUOTE`）。条目也可以完全没有 `quote`。

### 15E 立场仍然只在视角层

`scene` 里不许出现评价词（辉煌／骄傲／瑰宝／伟大…，与 `validate-achv` 同词表），落在引号对内的
文献原话与书名号里的专名豁免（`STORY_STANCE`）。极值语（最早／第一次／首次／领先／之最／唯一…）
不禁止说，但禁止不说凭什么：必须带非空 `caveat` 写清凭哪本账、谁后来怀疑过（`STORY_SUPERLATIVE`）。

### 15F 两片新分片时最容易漏的两处

1. **守卫行**：每个分片第一行必须自己写
   `window.__CHRONICLE_STORY_CHUNK = window.__CHRONICLE_STORY_CHUNK || {};`
   漏了它在浏览器里**不发作**（前一片已把全局建好），只有逐片在全新 `vm` 沙箱里独立求值才现形。
   这颗雷在生产数据里真撞到过一次（`songyuan.js`），现在是 `tools/test-story.mjs` 的常驻用例。
2. **登记**：写完文件必须在 `data/story/manifest.js` 的 `chunks` 里加一条。界面按 manifest 注入，
   没登记的分片永远加载不到——磁盘上有、读者看不到，而且除了这道门没人知道。
   反方向同样判红：manifest 登记了磁盘上没有的，注入直接 404。

### 15G 必跑

```bash
node tools/validate-story.mjs   # 门：动过 data/story/ 任何一片或 manifest.js 之后
node tools/test-story.mjs       # 门能红：每个码各被定向打红一次，豁免边界各判绿一次
```

`test-story.mjs` 的夹具是 9 片 × 32 条，刻意压在 `STORY_COVERAGE` 线**之上**：夹具若本来就小于下限，
那满屏的「红」只证明夹具小，不证明门有效。它的最后一组用例把检查码清单从 `validate-story.mjs`
源码现取（头部注释登记的、与 `bad()` 实际发出的，两侧对账），再比对哪些码真被打红过——
所以「加了一个码、忘了写用例」和「注释里有、代码从不发」都会在这里露出来，
而不是靠文档里一句写死的数字。

## 16. 日层契约（`data/dates.js`：「历史上的今天」唯一可以引用的日子）

这一层与其余各层的根本区别：**它不存事实，它存「事实自己的文本里已经写明的日子」**。
所以它不是手写的、也不能手写。

### 16A 口径（唯一出处：`tools/date-lib.mjs`，候选器与门共用一份）

按层自上而下，命中即止；`how` 就是命中的那一层，界面按它区别标示：

| `how` | 取自 | 界面必须说的话 |
| --- | --- | --- |
| `text` | `title` / `summary` 里的「X年Y月Z日」 | 正文纪日 |
| `process` | `detail.process` 里的同形日期 | 经过段纪日 |
| `src` | 只在 `detail.sources` 里 | **出处纪日**：那是文书落款那一天，不等于事件发生日 |
| `text-cn` | `title`/`summary`/`process` 里的中文月日（「十二月十三日」） | 中文纪日；只收 1912 年及以后 |

四条硬律，改动任何一条就是改语义，必须连 `date-lib`、`date-candidates`、`validate-dates`、
`README` 与本节一起改，并换 `DATE_RULE` 的版本号：

1. **年份必须等于本条的 `year`**。别的年份的日子属于别的事件，挂过来就是造假。
2. **同年出现两个不同日子 ⇒ 判歧义，整条不收**，两个候选交回写正文的人（`--ambig`）。
   门不许替人挑一天——挑了就没有第二双眼睛了。实测这类条目 72 条（数字以门读数为准）。
3. **`background` / `impact` / `related` 一律不查**：那几段天生要提别的事件的日期。
4. **中文月日只收 1912 年及以后**，且前面出现「农历/旧历/阴历/夏历/闰」即跳过。
   此前的人写中文月日多半是农历，换算要历表；历表错一次就是把日期造假，所以一律不收。

### 16B 记录形制

```js
window.__CHRONICLE_DATES = {
  version: 1,
  rule: "same-year|text>process>src|cn1912|v1",
  prolepticBefore: 1583,   // 界面读它，不抄它
  ambiguousCount: 72,      // 页脚读它，也不抄
  blankDays: 10,           // 页脚的「空 N 天」，同样只读不数
  mdays: [31,29,31,30,31,30,31,31,30,31,30,31],  // 各月天数：判断「这天存不存在」唯一凭据
  recs: [ { id: "cn--1949--p01", m: 9, d: 22, how: "src" } ]
};
```

`recs` 按 `id` 字典序、一记录一行。**这个文件是生成物**：`node tools/date-candidates.mjs --apply`
（幂等，内容相同不写）。手打一个字，`DATES_DERIVE` 会现算并与盘上逐字比对后判红。

`prolepticBefore` 与 `ambiguousCount` 之所以进了生成件而不是让界面自己写：
`js/today.js` 的页脚要说「早于该年者按后世历表推定」和「另有 N 条因歧义不收」，
这两个数一旦在界面里写死就成了第二份，两份打架时没人知道该信哪个——
`DATES_RULE` 盯着前者、`DATES_DERIVE` 盯着后者，`test-dates.mjs` ⑧ 另查界面确实只读盘上的数。

`blankDays` 是同一个道理，而且它虚报过一次：界面与门各写一遍 `d <= 31` 的循环，
4/31、6/31、9/31、11/31 这四个根本不存在的日子就被数成「空着的一天」，页脚当着读者的面
报「空 14 天」，实况 10 天（366 格 − 命中 356 格）。现在格子由 `date-lib.mjs` 的
`blankCells(recs)` 按 `MDAYS` 数——只有这一份；`blankDays` 与盘上 `recs` 现算的结果对不上就
`DATES_DERIVE`，界面里再出现自己数日历格的循环则由 ⑧ 判红（三条判据各有 test-gates-meta 哨兵）。
读不到 `blankDays` 时页脚把这半句整个省掉，不印一个 0。

`mdays`（各月天数）管的是另一件事：**深链能写出日历上不存在的日子**。`#/today/4/31`、`#/today/2/30`、
`#/today/13/1` 都是合法的 URL 字符串，而把「4 月 31 日」画成标题就是这一层唯一一种会被读者当成史实的造假。
所以这张表也进生成件，`js/today.js` 的 `cellExists()` 只读它：不存在就照实说一句「这个日子不存在」并落回
读者的今天（地址不改写——读者复制到的还是他贴出去的那条，重新打开同样得到这句解释）。
这一处踩过一次两面怪：`js/router.js` 原先自己抄了一份「二月 29 天、其余按 31 天」的表，于是同一类地址两条路——
4/31 放到了界面（界面会说），2/30 被路由默默吞掉（读者被送回今天，不知道为什么）。现在路由不判，
`test-dates.mjs` ⑧ 钉住「`js/router.js` 里没有第二张历表」；`DATES_RULE` 钉住盘上 `mdays` 与 date-lib 一致、
`DATES_SCHEMA` 钉住 `mdays` 是 12 项。

### 16C 检查码（`tools/validate-dates.mjs`）

`DATES_FILE`（缺失／语法塌／`recs` 不是数组）、`DATES_RULE`（口径版本、`prolepticBefore`、`mdays` 与 date-lib 不同步）、
`DATES_SCHEMA`（字段缺失、类型不对、月日越界如 2-30、`how` 不在四层内、`mdays` 不是 12 项历表、数组里多一个逗号就是个洞）、
`DATES_DUP`（同 id 两次）、`DATES_ID`（条目已删而日层留着）、
`DATES_DERIVE`（盘上 ≠ 现算、该收没收、`ambiguousCount`／`blankDays` 与现算不符或缺项）、
`DATES_MISSING`（生成器没跑完就提交）、`DATES_COVERAGE`（总量或命中日历格掉到地板以下、
空格数越过天花板——「历史上的今天」会在某些日子悄悄空掉）。

### 16D 必跑

```bash
node tools/date-candidates.mjs          # 只读：收了多少、哪些格空着、哪几条歧义
node tools/date-candidates.mjs --apply  # 落盘 data/dates.js
node tools/validate-dates.mjs           # 门
node tools/test-dates.mjs               # 门能红：改盘会红、改正文也会红，且 --apply 后必须回绿
```

日门与别的内容门不同，它对**两侧**都敏感，所以自审必须两侧都打红：改 `data/dates.js` 会红，
改条目正文里那句纪日也会红；第三件事是「改完正文重跑 `--apply` 就能绿」——那是三件不同的事，
每一件都得有人证明它真会发生，否则哨兵自己就是假门。夹具从当前日层运行时挑（硬编码 id 必腐），
前置条件构造不出来即判失败、不许静默 skip。

## 17. 涟漪层契约（`data/chain/`：大事的余波落在后来的小事上）

这一层与其余各层的根本区别：**它写的不是事实，是事实之间的关系**。事实层说哪一年发生了什么，
故事层说当时那人手上是什么情形，涟漪层说的是「因为 A，所以后来有了 B」——它是在替历史编因果。
读者分不清「史书这样写了」和「本站这样连的」，而后者一旦被当成前者，造假就不是写错一条，
而是凭空造出一条从来没人主张过的关系。所以本层是全站风险最高、也是判据最硬的一层。

### 17A 四条硬律（机器版本：`tools/validate-chain.mjs`；改任何一条口径必须连门、界面图例、本节一起改）

1. **每一环的 `ev` 必须真在 `data/cn`·`data/wd` 里，年份与权重一律由锚点派生。**
   本层不存 `year`、不存 `weight`、不存 `date`——各存一份就有第二份打架的（同 §15 故事层那条）。
   链的年代跨度、首末年份、每环权重，全部现场从锚定的条目读。
2. **环序按年份严格递增，且平均每环至少隔三年。**
   同年并列不排：谁先谁后本站无从判断，排了就是编。首末差 < 3×(环数−1) 判红——
   一串紧挨着的事排成一行不是涟漪，是另一份年表。
3. **每一边必须写明「有出处」还是「本站的连接」，两者界面同等显眼。**
   说「有出处」时，所引材料名必须**逐字**出现在这一边**两端条目自己的 `detail.sources`** 里。
   本站无权凭空造一个书名。连不上的那一段就照实标「本站的连接」——一条链允许有这样的边，
   但不允许全是（`CHAIN_GROUNDED`：全靠推断的链条不该进这一层）。
   与故事层的 `verbatim` 判据不同：那边要求定位到篇目卷页，因为逐字引文错一个字就是造假；
   这里只要求「这本书确实是这一环依据的材料」，书名级也够读者去查，
   界面会照 §6A 四级如实标出它到了哪一级（仅书名就显示仅书名）。
4. **末环（落点）必须是当时看来很小的事（`weight ≤ 2`）。**
   涟漪的定义是「大事的余波落在小事上」；落点本身是大事，这条链就退化成另一份大事年表。
   这条口径承认一件事：`weight` 是本站对重要性的打分，用它定义涟漪等于用本站的口径定义涟漪——
   界面图例里同样这样写，不做遮掩。

### 17B 一条链的形状

```js
window.__CHRONICLE_CHAIN_CHUNK = window.__CHRONICLE_CHAIN_CHUNK || {};   // 守卫行必须有，见 §15F
window.__CHRONICLE_CHAIN_CHUNK["ancient"] = [
  {
    id: "ch-ancient-001",
    title: "为求一匹马，六万人西行又东出",
    links: [
      { ev: "cn--b138--x01",                     // 环 = 一条真条目；首环只给 ev
        claim: "张骞回报大宛有善马，朝廷此后数次西征，都从这里起念。",   // 非末环必须有 claim
        basis: "有出处", prov: ["《史记·大宛列传》"] },   // 末环不许带 basis/prov
      { ev: "cn--b99--m02" }                     // 落点：小事，只给 ev
    ],
    caveat: "两次伐大宛与天山一击之间，本站连的是兵源与调度，不是《史记》里的明文……因果是推定。"
  }
];
```

- `links` 3–6 环；非末环必带 `claim`（那句「于是」的下文），末环必不带 `claim`（落点不替它编意义）。
- `basis` 二选一：`有出处` 必带 `prov`（材料名数组）；`本站的连接` 必**不**带 `prov`。给了就是自相矛盾。
- `caveat` 每链必填，且必须**真的在怀疑这条链**：既含存疑词（推定/或者/未必/无从确知…），
  又有一句在说这条连接本身哪里站不住。写「此事尚有争议」这种放之四海而皆准的废话不算。
- 分片按**首环年代**切（≤1500 / >1500），不按朝代切：一条链天生跨朝代，按朝代分会把链撕成两半。

### 17C 检查码（`tools/validate-chain.mjs`）

`CHAIN_FILE`（目录／manifest 缺失或求值塌了）、`CHAIN_MANIFEST`（manifest 与磁盘分片不一一对应——
漏登记的分片界面永远加载不到）、`CHAIN_SCHEMA`（字段缺失、类型不对、多存了 `year`/`weight`、
`id` 形态不合、末环私带 `basis`/`prov`）、`CHAIN_DUP`（链 id 重复；同一条链里同一个 `ev` 出现两次——
同一事件连两次等于环序是编的）、`CHAIN_ANCHOR`（锚点不在语料里）、
`CHAIN_ANCHOR_PROV`（锚点条目自己没有任何出处，这一环悬空）、`CHAIN_ORDER`（环序非严格递增，含同年）、
`CHAIN_LINKS`（环数越界、末环带 `claim`、非末环缺 `claim`）、`CHAIN_SPAN`（平均每环不足三年）、
`CHAIN_SMALL`（落点不是小事）、`CHAIN_BASIS`（`basis` 不在二值内、有出处却无 `prov`、自连却给了 `prov`）、
`CHAIN_PROV`（所引材料在这一边两端的 `sources` 里找不到——凭空造书名）、
`CHAIN_GROUNDED`（整条链没有一个「有出处」的边）、`CHAIN_CAVEAT`（缺、过短、不含存疑词、
或没有一句在说这条连接本身）、`CHAIN_CROSS`（跨轨链过少，或某一片首环全挤在同一世纪——链条没铺开）、
`CHAIN_STANCE`（评价词漏进 `title`/`claim` 且不在引号对内；立场仍只许写在视角层）、
`CHAIN_COVERAGE`（链总数／分片数／单片链数低于下限，或同一个 `ev` 被过多条链复用）。

`CHAIN_STANCE` 用的引号对内豁免与 §14 同一份实现（`tools/voice-lib.mjs`），本层不自写第二套判据。

### 17D 必跑

```bash
node tools/validate-chain.mjs   # 门：动过 data/chain/ 任何一片或它的 manifest.js 之后
node tools/test-chain.mjs       # 门能红：17 个码各被定向打红一次 + 豁免边界各判绿一次
```

`test-chain.mjs` 的夹具必须是**生产形态**（分片数、每片条数都压在 `CHAIN_COVERAGE`／`CHAIN_CROSS`
线之上做减法）：夹具若本来就小于下限，满屏的「红」只证明夹具小、不证明门有效。
检查码清单从 `validate-chain.mjs` 源码现取（注释登记与 `bad()` 实发两侧对账，再比哪些码真被打红过），
所以「加了一个码、忘了写用例」和「注释里有、代码从不发」都会在这里露出来。
最后一组用例另管界面接线：模块与样式是否真挂上 `index.html`、路由/Esc/`B` 键/顶栏按钮四条入口、
互相关闭的窗口、抽屉与详情与投稿弹窗的 z 序、`[hidden]` 的 `display` 兜底，
以及两种 `basis` 在视觉上必须同级（一处用虚线一处用实线可以，一处淡到 `--ink-faint` 就不行——
淡下去的那一档，读起来就成了「这句不算数」）。

### 17E 本层的三个盲区，写在门里而不是藏在心里

1. 本门验的是**材料名对不对得上**，不验「材料里有没有这句话」。把《史记·大宛列传》当作
   「大宛之战导致天山出击」的凭据，形态上能过，真去翻的人才有结论。
   所以界面上「有出处」一律写成「本站据以连接的材料」，不写成「史料记载」。
2. 因果的强弱、有没有第三变量，本门一概不知。它只保证一件事：不许把话说成不是自己说的话。
3. `SPAN`／`SMALL`／`CROSS` 三条阈值都是落盘当日的实测下位整数，是**回归线不是目标线**：
   补充链条时该抬的是内容，不是先把线抬高。
